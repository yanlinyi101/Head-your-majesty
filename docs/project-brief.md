# 《Heads Off Party》项目思路固化文档

> 暂定名：Heads Off Party / 陛下，头掉了！  
> 类型：单场景高密度物理派对小品  
> 当前目标：用一个可控小项目验证美术资产、Godot 3D 技术路径、物理喜剧手感和 Steam 题材吸引力。
>
> **GitHub 仓库**: https://github.com/yanlinyi101/Head-youryour-majemajesty

---

## 1. 项目一句话

四个没头角色在革命后的巴黎广场抢各种脑袋，戴上不同脑袋获得荒诞能力，谁能戴着“国王头”坚持最久谁获胜。

---

## 2. 核心判断

当前阶段不适合直接做大型 RTS 或完整在线派对游戏。

更优策略是：

> 单一场景，但把交互密度、笑点密度、反馈密度做深。

这个项目不是为了证明“内容量大”，而是为了验证：

- 玩家是否能在 30 秒内看懂玩法；
- 抢头、戴头、掉头、滚头是否天然好笑；
- Godot 3D 角色控制和物理反馈是否可行；
- 低成本卡通资产能否支撑 Steam 页面观感；
- 单一高密度场景能否产生可传播的短视频片段；
- 未来是否有扩展成派对游戏或更完整作品的空间。

---

## 3. 核心卖点

### 3.1 视觉卖点

- 没头角色乱跑；
- 头在地上滚；
- 玩家戴错头后获得奇怪能力；
- 所有人围绕一个头发生混乱争抢；
- 法国大革命、断头台、国王、鸡头、炮弹头等元素形成荒诞反差。

### 3.2 玩法卖点

- 抢头；
- 撞人；
- 戴头获得能力；
- 丢头砸人；
- 头被撞飞后形成连锁反应；
- 单局 3 分钟，快速产生胜负和笑点。

### 3.3 传播卖点

适合剪成 15–30 秒短视频：

- “国王头被撞飞滚进喷泉”；
- “鸡头玩家扑腾过去抢头结果摔倒”；
- “炮弹头玩家撞飞别人也把自己弹飞”；
- “所有人抢同一个头，最后头弹回断头台”。

---

## 4. 推荐项目定位

### 4.1 类型

单场景 / 本地多人 / BOT 可玩 / 物理派对乱斗。

### 4.2 不做什么

MVP 阶段不做：

- 在线多人匹配；
- 大量地图；
- 剧情战役；
- 复杂技能树；
- 长流程关卡；
- 过多角色差异；
- 完整商业化系统；
- 复杂 AI 决策。

### 4.3 做什么

MVP 阶段只聚焦：

- 一个场景；
- 一个模式；
- 四个角色；
- 五种头；
- 三分钟一局；
- 强反馈物理互动；
- 可录制搞笑片段。

---

## 5. 核心玩法循环

```text
移动追逐
  ↓
看到头
  ↓
冲撞 / 捡头 / 丢头
  ↓
戴上头获得能力
  ↓
被撞飞或撞飞别人
  ↓
头掉落并滚走
  ↓
所有人重新争抢
  ↓
持有国王头计分
  ↓
时间结束，分数最高者获胜
```

核心不是复杂操作，而是制造连续反应链。

---

## 6. 基础操作设计

MVP 只保留四个操作。

| 操作 | 作用 | 设计目标 |
|---|---|---|
| 移动 | 跑、躲、追 | 简单直觉 |
| 冲撞 | 撞飞别人、撞掉头 | 制造物理冲突 |
| 捡头 / 戴头 | 获得能力 | 形成身份变化 |
| 丢头 | 把头当投掷物砸人 | 制造反转和笑点 |

不建议第一版加入普通攻击、技能栏、装备栏、任务系统。

---

## 7. 第一版头部道具设计

MVP 只需要 5 个头。

| 头 | 能力 | 负面效果 | 笑点 |
|---|---|---|---|
| 国王头 | 持有时持续得分 | 移动变慢 | 所有人追你 |
| 鸡头 | 短距离跳跃 / 扑腾 | 落地不稳定 | 咯咯叫乱飞 |
| 炮弹头 | 冲撞更强 | 自己也容易被弹飞 | 撞人也撞飞自己 |
| 南瓜头 | 滚动加速 | 转向困难 | 失控撞墙 |
| 法官头 | 短暂定身别人 | 技能前摇明显 | 喊“肃静”后被反杀 |

---

## 8. 单一场景设计

### 8.1 场景主题

革命后的巴黎广场。

### 8.2 地图结构

建议做成小型竞技场，而不是开放大地图。

```text
┌──────────────────────┐
│  摊位区     路障区    │
│                      │
│      中央断头台       │
│      头部刷新点       │
│                      │
│  喷泉区     马车区    │
└──────────────────────┘
```

### 8.3 场景元素

| 区域 | 功能 |
|---|---|
| 中央断头台 | 核心争夺点，头部刷新点 |
| 喷泉 | 头会滚进去，玩家可能被弹开 |
| 木箱 / 路障 | 阻挡、碰撞、制造混乱 |
| 马车 | 周期性移动或作为障碍 |
| 台阶 | 让头滚下去，制造追逐 |
| 摊位 | 可撞翻，制造视觉反馈 |
| 围观群众 | 背景气氛和喜剧感 |
| 旗帜 / 告示牌 | 强化革命后巴黎氛围 |

### 8.4 场景设计原则

每 3 秒应该发生一次有趣反馈：

- 撞飞；
- 掉头；
- 头滚走；
- 角色摔倒；
- 场景物件被撞翻；
- NPC 围观反应；
- 音效或台词触发。

---

## 9. 反应链设计

玩家真正记住的不是地图数量，而是荒诞瞬间。

目标是形成这种反应链：

```text
A 戴上国王头变慢
B 用炮弹头撞 A
A 的头飞出去
头滚进喷泉
C 戴鸡头跳过去抢
D 丢南瓜头砸 C
所有人一起摔倒
国王头弹回断头台
```

这类连锁反应是项目的核心乐趣。

---

## 10. 美术风格建议

### 10.1 总体风格

卡通、低多边形、纸片剧场、布偶感、荒诞历史喜剧。

### 10.2 避免方向

不建议走：

- 写实血腥；
- 真实处刑；
- 强烈喷血；
- 猎奇断头；
- 过度阴暗恐怖；
- 历史仇恨煽动。

### 10.3 建议表达

“断头”可以通过喜剧化方式处理：

- 头像玩具球一样滚动；
- 血液用红丝带、番茄酱、红颜料替代；
- 断头台作为舞台道具，不做写实处刑；
- 角色身体像木偶、布偶、纸片人；
- 被撞飞时夸张弹性动画。

---

## 11. Steam 审核与题材风险

### 11.1 基本判断

“给路易十六找头 / 没头国王抢头”本身不是 Steam 国际版禁区。

风险不在题材，而在表现方式。

### 11.2 低风险表达

- 荒诞历史喜剧；
- 卡通物理；
- 无写实血腥；
- 无现实政治煽动；
- 无仇恨表达；
- 无成人色情内容；
- 无侵权素材。

### 11.3 高风险表达

- 写实断头；
- 喷血肢解；
- 处刑特写；
- 猎奇恶心作为核心卖点；
- 羞辱尸体；
- 影射现实群体仇恨；
- 商店页主图过度血腥。

### 11.4 推荐商店定位标签

可考虑：

- Comedy
- Party Game
- Physics
- Local Multiplayer
- Funny
- Historical
- Casual
- Singleplayer / Multiplayer，视实际支持而定

## 12. MVP 范围

### 12.1 MVP 目标

做出一个像“完整游戏切片”的小版本，而不是半成品技术 Demo。

### 12.2 内容范围

| 模块 | MVP 做法 |
|---|---|
| 视角 | 俯视 / 斜俯视小竞技场 |
| 角色 | 4 个同模型换色 |
| 场景 | 1 张巴黎广场 |
| 头部道具 | 5 个 |
| 模式 | 抢国王头，坚持计分 |
| 对局时长 | 3 分钟 |
| AI | 3 个简单 BOT |
| 联机 | 暂不做在线联机 |
| 本地多人 | 可后置，优先 BOT 可玩 |
| UI | 开始、计分、倒计时、结算 |
| 音效 | 碰撞、掉头、戴头、胜利、滑稽台词 |
| 目标 | 可录制 30 秒搞笑视频 |

## 13. 开发阶段规划

### Phase 1：7 天灰盒原型

目标：验证抢头是否好笑。

内容：

- 一个灰盒广场；
- 一个无头角色；
- 一个可捡头物体；
- 戴头 / 掉头逻辑；
- 头会滚动；
- 简单冲撞；
- 一个弱智 BOT；
- 基础计分逻辑。

验收标准：

- 玩家能捡头；
- 玩家能戴头；
- 被撞后头会掉；
- 头掉落后会滚动；
- 玩家会主动想去抢头；
- 旁观者能看懂发生了什么。

---

### Phase 2：14–21 天可展示版

目标：做出可录视频、可发社媒的版本。

内容：

- 4 个角色；
- 5 个头；
- 1 张卡通巴黎广场；
- 3 个 BOT；
- 1 个完整计分模式；
- 开始和结束 UI；
- 基础音效；
- 夸张碰撞反馈；
- 30 秒宣传视频素材。

验收标准：

- 3 分钟一局；
- 有明确胜负；
- 每局至少出现 3 个搞笑瞬间；
- 30 秒视频能让人看懂“没头抢头”；
- 玩家愿意再来一局。

---

### Phase 3：Steam 页面级原型

目标：验证 Steam 愿望单潜力。

内容：

- 更精致的场景；
- 更稳定的控制手感；
- 手柄支持；
- 本地多人支持；
- 2–3 张宣传截图；
- 1 条 30–60 秒 Trailer；
- Steam Coming Soon 页面；
- 简短可玩 Demo。

验收标准：

- Steam 页面一眼能看懂卖点；
- Trailer 前 5 秒出现核心笑点；
- 玩家愿意加入愿望单；
- 没有明显 bug 和崩溃；
- 手柄和键鼠操作都能玩。

---

## 14. 关键验收指标

| 指标 | 标准 |
|---|---|
| 30 秒可理解 | 看视频的人知道在抢头 |
| 3 分钟一局 | 有胜负、有反转 |
| 5 分钟愿意再玩 | 至少愿意玩第二局 |
| 每局笑点 | 至少出现 3 个可剪辑瞬间 |
| 操作复杂度 | 新玩家 1 分钟内掌握 |
| 页面卖点 | 一张图能说明“没头抢头” |
| 技术验证 | Godot 3D 控制、物理、换头、BOT 跑通 |
| 美术验证 | 低成本角色和场景资产能支撑观感 |

---

## 15. 最大风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 物理不好笑 | 碰撞太硬、太轻或不可控 | 重点调手感，不追求真实物理 |
| 目标不清楚 | 玩家不知道为什么抢头 | 国王头高亮、UI 计分明确 |
| BOT 太蠢 | 没有对抗感 | BOT 只需要会追头、撞人、逃跑 |
| 场景太空 | 单场景但没有交互密度 | 增加障碍物、台阶、喷泉、可撞翻物 |
| 题材变猎奇 | 断头表达太血腥 | 坚持卡通、布偶、纸片剧场风 |
| 做大失控 | 加太多地图和机制 | MVP 严格限制 1 场景、5 个头、1 模式 |

## 16. 设计原则

### 原则一：少内容，高密度

不要追求地图多、角色多、模式多。

先把一个场景打磨到：

- 能看懂；
- 能玩；
- 能笑；
- 能录视频；
- 能复玩。

### 原则二：物理反馈优先

搞笑派对游戏的关键不是数值深度，而是反馈。

优先打磨：

- 撞飞力度；
- 掉头时机；
- 头滚动路径；
- 摔倒动画；
- 音效；
- 屏幕震动；
- 胜负瞬间。

### 原则三：每个头都要有“能力 + 缺陷”

如果头只有正向能力，会变成普通道具。

每个头都应该既强又蠢：

- 国王头能得分但变慢；
- 炮弹头撞人强但自己失控；
- 南瓜头跑得快但转向差；
- 鸡头能跳但落地不稳。

### 原则四：不要做写实断头

这个项目的方向是荒诞喜剧，不是猎奇暴力。

所有血腥元素都应该舞台化、玩具化、卡通化。

## 17. 后续可扩展方向

如果 MVP 成功，可以扩展：

### 17.1 更多头

- 小丑头；
- 骷髅头；
- 面包头；
- 猫头；
- 鸭头；
- 哲学家头；
- 炸弹头；
- 磁铁头。

### 17.2 更多地图

- 巴黎广场；
- 凡尔赛厨房；
- 革命法庭；
- 地下酒窖；
- 马车街道；
- 王宫舞厅。

### 17.3 更多模式

- 抢国王头；
- 头球足球；
- 断头台躲避赛；
- 谁是真头；
- 合作找头；
- 限时逃脱。

### 17.4 更强派对化

- 本地 4 人；
- Steam Remote Play Together；
- 简单在线房间；
- 创意工坊头部道具；
- 自定义角色皮肤。

---

## 18. 当前最推荐的下一步

不要立刻做完整游戏。

下一步只做 Phase 1：

> 一个灰盒场景 + 一个无头角色 + 一个可抢的头 + 掉头 / 滚头 / 戴头 / 撞人。

只要这个原型在灰盒阶段已经好笑，就值得继续。

如果灰盒阶段不好笑，不要靠美术硬救，说明核心互动需要重调。

---

## 19. 当前项目定义总结

《Heads Off Party》是一个用于路径验证的小型物理派对项目。

它的核心价值不是内容规模，而是：

- 题材一眼记住；
- 机制简单直觉；
- 物理反馈搞笑；
- 单场景高密度；
- 容易录制传播；
- 可作为未来派对游戏或动物 RTS 美术技术栈的前置验证。

最终方向：

> 做一个 3 分钟一局、一个场景就能笑出来的“没头抢头”物理派对小品。
